# miku-repo-bundle

`miku-repo-bundle` creates a repository reference bundle from a cloned
repository.

The bundle is intended for generative AI tools and coding agents. It packages
repository metadata, source files, reference documents, a class index, artifact
notes, and an optional jar artifact so the receiver can inspect the project as
reference material.

## Purpose

`miku-repo-bundle` is a reference bundler, not a build system.

It prepares the kind of repository exploration and organization that an AI
agent often performs before starting work. The generated files should be
treated as reference-only material. They are not modification targets.

## Basic Usage

```bash
miku-repo-bundle ./repo --output ./dist/repo-reference
```

Recommended usage is to pass an existing jar whenever possible:

```bash
miku-repo-bundle ./repo \
  --output ./dist/repo-reference \
  --artifact ./repo/target/app.jar \
  --entry com.example.Main
```

External documentation directories can also be included:

```bash
miku-repo-bundle ./repo \
  --output ./dist/framework-reference \
  --artifact ./repo/target/framework.jar \
  --docs ./framework-docs \
  --docs ./migration-notes
```

## Runtime Requirement

`miku-repo-bundle` requires `miku-text-bundle` at runtime.

The text part of the repository reference bundle is generated by running
`miku-text-bundle` over an intermediate input directory prepared by
`miku-repo-bundle`. If `miku-text-bundle` is not available, `miku-repo-bundle`
should fail with a clear diagnostic instead of trying to create its own partial
text bundle.

## Output Layout

The default output is a folder, not a zip.

Example output:

```text
repo-reference/
├─ MANIFEST.md
├─ text-bundle-000-prompt.md
├─ text-bundle-001.md
├─ text-bundle-002.md
├─ text-bundle-999-index.md
└─ artifact.jar
```

`artifact.jar` is included only when an artifact is available.

Source files are included in `text-bundle-001.md` and following text bundle
parts. They are not stored as separate source files in the output folder. Use
`text-bundle-999-index.md` to find which text bundle part contains a specific
source file.

## MANIFEST.md

`MANIFEST.md` is the entry file for the final output folder.

It should explain:

- this is a repository reference bundle
- files in the bundle are reference-only
- source code is inside the text bundle part files
- `artifact.jar` is binary reference material
- the receiver should read `text-bundle-000-prompt.md` after `MANIFEST.md`

Minimum read order:

```yaml
bundle_type: repository_reference
purpose: reference_only
modification_policy: do_not_modify
read_order:
  - MANIFEST.md
  - text-bundle-000-prompt.md
  - text-bundle-001.md
  - text-bundle-002.md
  - text-bundle-999-index.md
  - artifact.jar
```

## Text Bundle Contents

`miku-repo-bundle` prepares an intermediate text input directory and uses the
`miku-text-bundle` output for the text part of the reference bundle.

The text bundle should contain:

- repository metadata
- source files
- repository documents
- external documentation from `--docs <dir>`
- `class-index.jsonl`
- artifact notes
- artifact checksum

`artifact.jar` is not included in the text bundle. It is copied beside the text
bundle files as a binary sidecar.

## Artifact Policy

Prefer `--artifact <jar>` whenever possible.

Large repositories can take a long time to build. They may also require private
settings, profiles, environment variables, network access, credentials, or
local services. For that reason, `miku-repo-bundle` should not silently build a
repository.

Artifact handling is ordered as follows:

1. If `--artifact <jar>` is specified, the given jar is copied into the final
   output folder as `artifact.jar`.
2. If `--artifact` is not specified and `--build` is specified, the tool may try
   to build the repository with Maven or Gradle.
3. If neither `--artifact` nor `--build` is specified, the bundle is generated
   without `artifact.jar`.

`--artifact` and `--build` should not be used together.

## Build Fallback

`--build` is an explicit fallback for repositories that can be built locally in
a simple way.

Expected first behavior:

- Maven repositories: try `mvn package`
- Gradle repositories: try `./gradlew build` or `gradle build`

Build failure should be reported clearly. The tool should not hide build errors
or pretend that an artifact exists.

## Documentation Collection

Repository documentation is part of the reference bundle.

The tool should collect repository-local documents when present:

- `README.md`
- root-level `*.md`
- `docs/**/*.md`
- `CHANGELOG.md`
- `CONTRIBUTING.md`
- `LICENSE`

External documentation can be added with repeated `--docs <dir>` options. This
is useful when framework documentation, migration notes, or AI-facing reference
notes live outside the cloned repository.

Repository-local documents and external documents should be kept separate in
the intermediate text input so the receiver can understand their origin from the
text bundle.

## Processing Outline

1. Read repository metadata:
   - repository name
   - branch
   - commit hash
2. Resolve artifact:
   - use `--artifact <jar>` when specified
   - optionally try `--build` when explicitly requested
3. Generate class index:
   - call `miku-javaclass2json-java` when a jar artifact is available
   - write `class-index.jsonl` into the text bundle input
4. Collect source and project files:
   - `src/main/java`
   - optionally `src/test/java`
   - build files such as `pom.xml`, `build.gradle`, and `settings.gradle`
5. Collect documentation:
   - repository-local Markdown and support documents
   - external `--docs <dir>` directories
6. Generate artifact notes and checksum when an artifact is available
7. Run the text bundling step to generate `text-bundle-*.md`
8. Generate final `MANIFEST.md`
9. Copy `artifact.jar` as a sidecar when available

## AI Usage

Pass the final output folder to the target generative AI tool as uploaded files
or as an uploaded code folder when available.

Use a prompt like this:

```text
This folder is a repository reference bundle.
Read MANIFEST.md first.
The source code is included in text-bundle-001.md and following text bundle
parts.
artifact.jar is binary reference material. Prefer the class index and artifact
notes in the text bundle before reasoning from the jar.
Do not modify files from this bundle.
```

## Relationship to miku-text-bundle

```text
miku-text-bundle
  = bundles text into split Markdown files

miku-repo-bundle
  = prepares repository reference material, uses text bundle files for source
    and documents, and keeps jar artifacts as binary sidecars
```
